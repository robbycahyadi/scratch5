## B. Implementasi pipeline — desain tetap

4. Buat runner Python sederhana yang bisa diulang; manfaatkan sebanyak mungkin fungsi sumber yang sudah dibekukan (`split_train` boleh jadi referensi tetapi perlu indeks train/val/test lengkap, `prepare_generator`, `model_frame`, `synthetic_model_frame`, `round_counts`, `derive_semantic_columns`). Jangan memodifikasi implementasi generator beku jika bisa membungkus/mengekstrak logic secara aman ke runner baru. Bila refactor beku diperlukan karena blocker nyata, hentikan dan laporkan alasannya sebelum mengubah sumber.
5. Pastikan input raw dataset SHA256 `52e96b895b1112e1c853f670e58372719c8441c5ed1c57ac2f7fad559d784f5f`. Reproduksi **dua pemanggilan** `train_test_split` persis pada indeks baris dengan seed 42, test_size .30 lalu .50 atas holdout, stratify TARGET. Simpan checksum keanggotaan split; jangan membuat split berbeda. Train/validation/test = 215257/46127/46127, 120 fitur; keluarkan ID/TARGET dari fitur. Test dilarang untuk fit, generator, threshold, atau pemilihan parameter.
6. Terapkan pipeline model yang sama pada kelima metode. Fitur numerik model float64 dengan missing asli, sentinel hari→NaN; kategori `__MISSING__`, XNA/Unknown eksplisit dan satu `OrdinalEncoder(handle_unknown='use_encoded_value', unknown_value=-1)` fit **hanya kategori asli train**, lalu transform asli/semua sintetis/validation/test. Pastikan `-1` unknown bukan NaN dan tidak muncul untuk synthetic train. Tidak perlu native categorical XGBoost atau fitur/indikator baru.
7. Bentuk E/U dari raw 120 prediktor sebelum masking sentinel/imputasi: tau=.6, E=8636, U=8741, S=8636. Generator *global* M2 (2S) / M3 (S) mengambil seluruh minoritas train dengan input mayoritas train untuk API SMOTENC; M4 (S) hanya mengambil E, dengan mayoritas train pada input generator. Tetap `k_neighbors=5`, seed 42, train-only median dan StandardScaler. Gunakan `synthetic_model_frame` **bersama** untuk M2/M3/M4 setelah inverse scaling, koreksi 12 hitungan dan `DEF<=OBS`, sebelum encoder; jangan lakukan pada data asli atau mengubah pemilihan tetangga.
8. Terapkan sample weights persis: M0 asli semua 1; M1 positif asli 1+2S/n1; M2 asli semua 1, 2S sintetis berbobot 1; M3 positif asli 1+S/n1, S sintetis bobot 1; M4 E=1, U=1+S/nU, S sintetis bobot 1; mayoritas selalu 1. Verifikasi bobot efektif positif M1–M4 34649; M3 dan M4 masing-masing 8636 sintetis. Semua asli tetap ada, nama/urutan 120 fitur identik.
9. Gunakan `XGB_PARAMS` **persis** dari blok di `02_XGBOOST_PROTOCOL_USULAN.md` (XGBoost 3.4.1, tanpa hyperparameter search, early stopping, atau perubahan parameter antarmetode). Jangan menambahkan `scale_pos_weight` non-1 atau class balancing lain. Ekstrak parameter sekali ke konfigurasi terpusat jika masuk akal agar tidak terjadi drift.

## C. Gerbang uji integrasi — harus PASS sebelum evaluasi test

10. Buat tes terfokus yang melindungi invariants: split/ID terpisah; fitur tidak berisi SK_ID_CURR/TARGET; fit preprocessor train-only; kategori synthetic valid; original prefix sama persis; NaN struktural sintetis hanya sesuai dua masking; nilai bukan infinity; 12 hitungan valid, DEF<=OBS; jumlah synthetic M2/M3/M4 tepat; total bobot sama; kesetaraan feature schema dan encoder untuk 5 metode; semua metode menerima `sample_weight`; penentuan threshold deterministik (termasuk tie). Tes dengan **data buatan** seperlunya dan preflight pada data train asli agar integrasi global M2/M3 terbukti, bukan hanya unit test tiga nama metode.
11. Jalankan uji integrasi yang benar-benar mengaktifkan M2 dan M3 serta M4 tanpa akses evaluasi test. Verifikasi jumlah asli/sintetis, kategori/NaN/bobot, manifest, ketetapan split dan semantik. Boleh smoke fitting menggunakan data buatan/train-only **jika perlu** menguji API; jangan menggunakan validation/test sebagai fitting. Jika gagal, perbaiki bug implementasi minimum, ulang tes terdampak, dan **STOP sebelum test**. Jangan melonggarkan assertion atau mengubah desain untuk mengejar PASS.
12. Jika seluruh gerbang PASS, train **tepat lima XGBClassifier** pada train sesuai bobot, gunakan prediksi validation untuk threshold F1 per model (kandidat probabilitas unik, tie threshold terbesar; `p>=threshold`). Catat AP dan metrik validasi bila dibutuhkan untuk sanity check; jangan memilih model atau mengubah metode berdasarkan metrik validasi. Bekukan lima threshold dan artefak run, seed/versi/source/fit counts/checksum; simpan di `results/` yang ignored. Tidak ada early stopping atau fitting pada validation.
13. **Evaluasi final test hanya setelah** bukti uji integrasi PASS, semua lima model selesai train, kelima threshold telah dibekukan dan hasil/manifest pra-test disimpan. Lakukan satu evaluasi test alami dengan `average_precision_score` sebagai primer dan ROC-AUC, precision, recall, F1, confusion matrix sebagai pelengkap. Laporkan delta AP M4-M3 dan trade-off, termasuk bila negatif atau mendekati nol. Jangan gunakan test untuk memilih threshold, menyesuaikan parameter, mengulang training untuk mengoptimalkan skor, atau membuka perbandingan baru. Bootstrap berpasangan opsional **tidak** dijalankan secara otomatis.
