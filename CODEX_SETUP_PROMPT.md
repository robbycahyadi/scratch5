# Prompt satu kali untuk Codex — setup aturan kerja repo CG-HIL

Saya akan melanjutkan eksperimen tesis CG-HIL. **Tugas saat ini hanya mengaktifkan tata kelola minimal repo lokal**, BUKAN mengerjakan freeze generator (nomor 6), finalisasi XGBoost (nomor 7), atau training model.

Lakukan urutan berikut di root proyek yang sedang terbuka:

1. **Preflight read-only.** Identifikasi root direktori, daftar berkas yang ada, apakah repo sudah Git, branch/working tree/commit terakhir, apakah ada `.gitignore`, `AGENTS.md`, `AI_THESIS_WORKING_CONSTITUTION*`, `THESIS_STATE.md`, `EXPERIMENT_LOG.md`, dan laporan generator terbaru. Jangan menganggap folder kosong atau memindahkan file tanpa kebutuhan.
2. **Konstitusi asli.** Cari `AI_THESIS_WORKING_CONSTITUTION*` di root/workspace yang memang dapat diakses; jika tersedia di lokasi lain, salin byte aslinya ke root dengan nama/ekstensi yang tepat dan catat hash. **Jangan membuat ulang, menulis ulang, atau mengganti isinya.** Jika benar-benar tidak tersedia, laporkan bahwa mahasiswa harus menyalin berkas aslinya; jangan mengarang pengganti. File `AGENTS.md` tidak menggantikan konstitusi itu.
3. **Instruksi dan state.** Pastikan `AGENTS.md`, `THESIS_STATE.md`, dan `EXPERIMENT_LOG.md` dari paket handoff ada di root. Jika sudah ada versi yang berbeda, lakukan perbandingan dan gabungkan informasi baru secara konservatif; jangan overwrite riwayat atau keputusan lama secara diam-diam.
4. **Perlindungan Git.** Review `.gitignore` yang ada atau buat minimal `.gitignore` bila belum ada. Lindungi dataset Home Credit mentah (`application_train.csv`, `application_test.csv`, data mentah lainnya di folder data), `.env*`/credential, `.venv/`, cache, bobot/model binari, file sintetis besar, `results/` yang besar. Jangan blanket-ignore semua `.csv` atau `.md` karena kamus dan ringkasan bukti perlu bisa dilacak. Jika file sensitif telah ter-track, jangan rewrite history; laporkan risiko dan tindakan teraman.
5. **Git.** Jika Git belum diinisialisasi, pastikan lokasi yang benar dan tidak berada di dalam repo induk, kemudian lakukan `git init`. Jangan membuat remote/push. Jika Git sudah ada, pertahankan riwayat dan perubahan pengguna.
6. **Commit setup.** Jalankan pemeriksaan relevan untuk file yang diubah (`git diff --check`, cek daftar staged). Stage eksplisit hanya file governance hasil setup yang aman (mis. `AGENTS.md`, `THESIS_STATE.md`, `EXPERIMENT_LOG.md`, konstitusi asli, `.gitignore` bila aman). Buat commit yang jelas, contohnya `chore: establish CG-HIL thesis experiment guardrails`. Jika ada konflik perubahan atau berkas wajib tidak tersedia, jelaskan dan commit hanya bagian yang lengkap/aman; jangan membuat klaim palsu.
7. **Log.** Catat bahwa setup governance dilakukan dan hasil verifikasinya di `EXPERIMENT_LOG.md` sebelum commit. Jangan menulis hasil eksperimen, nomor commit historis, atau status pembekuan generator yang belum diverifikasi.
8. **Akhiri.** Laporkan file yang ada/ditambahkan, apakah konstitusi asli sudah tersalin, `.gitignore`, commit hash yang benar-benar dibuat, `git status --short`, isu yang tersisa, dan SATU langkah berikutnya. **Berhenti setelah setup**; jangan memulai nomor 6/7.

Aturan penting: gunakan AGENTS.md di root sebagai pedoman Codex, dan baca juga konstitusi kerja yang sudah tersedia. Hindari overengineering, tanpa sistem dokumentasi baru selain state, satu log, dan Git.
